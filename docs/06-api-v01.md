# API do v0.1

## `POST /upload`

Recebe um PDF completo do processo e dispara o processamento assincrono.

### Entrada

Multipart form:

- `file`: PDF do processo.

### Resposta

```json
{
  "processo_id": "proc_e91e5aa647b5",
  "status": "pendente"
}
```

### Status possiveis

- `pendente`;
- `processando`;
- `concluido`;
- `erro`.

## `GET /processo/{id}/status`

Retorna o estado do processamento.

### Resposta

```json
{
  "processo_id": "proc_e91e5aa647b5",
  "status": "concluido",
  "paginas_extraidas": 10,
  "chunks": 18,
  "erro": null
}
```

## `POST /processo/{id}/buscar`

Rota tecnica da Fase 3 para validar se a busca vetorial esta recuperando os
trechos corretos antes de ligar a resposta final por LLM.

### Entrada

```json
{
  "pergunta": "Quando sera a audiencia?",
  "top_k": 5
}
```

### Resposta

```json
{
  "processo_id": "proc_e91e5aa647b5",
  "pergunta": "Quando sera a audiencia?",
  "fontes": [
    {
      "pagina": 3,
      "chunk_index": 0,
      "tipo_documento": "audiencia",
      "score": 0.87,
      "trecho": "Designada audiencia..."
    }
  ]
}
```

## `POST /processo/{id}/chat`

Recebe uma pergunta e responde com base nos trechos recuperados do processo.

### Entrada

```json
{
  "pergunta": "Quais fatos preciso confirmar na audiencia?",
  "top_k": 5
}
```

### Resposta

```json
{
  "processo_id": "proc_e91e5aa647b5",
  "pergunta": "Quais fatos preciso confirmar na audiencia?",
  "resposta": "Os fatos a confirmar sao... [p. 3]",
  "modelo": "gemini:gemini-3-flash-preview",
  "fallback_usado": false,
  "modo_busca": "hibrida",
  "tempos": {
    "triagem_ms": 1,
    "recuperacao_ms": 96,
    "validacao_fontes_ms": 1,
    "geracao_ms": 21262,
    "avaliacao_ms": 0,
    "total_ms": 21365
  },
  "fontes": [
    {
      "pagina": 3,
      "chunk_index": 0,
      "tipo_documento": "audiencia",
      "score": 0.87,
      "trecho": "..."
    }
  ]
}
```

`tempos` separa as etapas percebidas pelo backend. Em uma execucao fria,
`recuperacao_ms` pode incluir a carga inicial dos modelos de embedding. O
perfilador `perfil-latencia-chat` detalha esse carregamento por modelo.

## Regra de Resposta

O modelo principal e `gemini:gemini-3-flash-preview`. Se ele falhar, o backend tenta
`groq:llama-3.1-8b-instant` como fallback.

Se o sistema nao recuperar fonte suficiente, responde que nao encontrou base no
processo, em vez de inventar.

## `POST /processo/{id}/transcricao-depoimentos`

Identifica os termos de oitiva, a pessoa ouvida e o corpo literal de cada fala.
O texto e devolvido por pagina e sem reescrita generativa. A versao atual do
contrato e 3.0.

```json
{
  "regenerar": false
}
```

## `POST /processo/{id}/comparacao-depoimentos`

Compara dois corpos literais ja identificados. O servidor valida os trechos e
vincula as paginas antes de devolver semelhancas e contradicoes potenciais.

```json
{
  "depoimento_a_id": "dep-p0010-depoimento_testemunha",
  "depoimento_b_id": "dep-p0018-interrogatorio_reu",
  "regenerar": false
}
```

A comparacao concluida pode ser recuperada em
`GET /processo/{id}/comparacao-depoimentos/{comparacao_id}`.

## `POST /processo/{id}/depoimentos/{depoimento_id}/perguntas-audiencia`

Gera ou reutiliza um roteiro fundamentado para a pessoa escolhida. Cada pergunta
inclui objetivo, prioridade e trechos literais com suas paginas.

```json
{
  "max_perguntas": 8,
  "regenerar": false
}
```

O roteiro persistido pode ser recuperado em
`GET /processo/{id}/perguntas-audiencia/{roteiro_id}`.

## `GET /processo/{id}/prescricao/dados`

Localiza candidatos de datas essenciais, artigos e penas no texto do processo.
Cada item inclui pagina, trecho e confianca, mas continua marcado para revisao.
A rota nao decide automaticamente quem e o reu nem qual artigo representa a
imputacao.

## `POST /processo/{id}/prescricao/calcular`

Calcula e persiste a prescricao da pretensao punitiva pela pena maxima em
abstrato. Os dados enviados nesta rota devem ter sido conferidos no processo.

```json
{
  "data_referencia": "2026-08-03",
  "reu": "Pessoa conferida",
  "data_nascimento_reu": "1990-01-02",
  "situacao_sentenca": "nao_proferida",
  "data_sentenca_condenatoria": null,
  "delitos": [
    {
      "id": "delito-1",
      "descricao": "Furto",
      "artigo": "Art. 155 do CP",
      "pena_maxima_meses": 48,
      "tipo_termo_inicial": "consumacao",
      "data_termo_inicial": "2020-01-10",
      "data_fato": "2020-01-10",
      "violencia_sexual_contra_mulher": false,
      "marcos_interruptivos": [
        {
          "tipo": "recebimento_denuncia",
          "data": "2020-03-15",
          "pagina": 7,
          "trecho": "A denuncia foi recebida em 15/03/2020."
        }
      ],
      "periodos_suspensao": []
    }
  ]
}
```

O resultado apresenta cada intervalo, a data-limite, o redutor do art. 115 e os
campos que impedem uma conclusao. O calculo pode ser reaberto em
`GET /processo/{id}/prescricao/calculos/{calculo_id}`.

O escopo juridico, as regras temporais e os limites estao documentados em
`docs/41-datas-essenciais-e-prescricao.md`.

## `POST /processo/{id}/estrutura-sentenca`

Estrutura sentencas, acordaos, pena aplicada, regime, multa e certificados de
transito em julgado sem usar LLM.

```json
{
  "regenerar": false
}
```

O resultado persistido pode ser recuperado em
`GET /processo/{id}/estrutura-sentenca`.

## `POST /processo/{id}/teses-defensivas`

Seleciona linhas defensivas de um catalogo juridico controlado. Cada tese
precisa de trecho literal favoravel e pode apresentar provas contrarias e
pontos pendentes.

```json
{
  "top_k": 36,
  "max_teses": 8,
  "regenerar": false
}
```

O resultado persistido pode ser recuperado em
`GET /processo/{id}/teses-defensivas`.

## `POST /processo/{id}/analise-nulidades/{tema}`

Gera uma analise fundamentada de um tema processual. `top_k` deve ficar entre
12 e 40.

```json
{
  "top_k": 24,
  "regenerar": false
}
```

O resultado informa a conclusao operacional, requisitos observados e nao
observados, prejuizo, contrapesos, trechos literais, paginas, fontes juridicas,
lacunas e providencias. A analise salva pode ser recuperada em
`GET /processo/{id}/analise-nulidades/{tema}`.

## `POST /processo/{id}/analise-nulidades`

Executa varios temas com persistencia individual. Quando `temas` estiver vazio,
os seis temas do motor geral serao analisados.

```json
{
  "temas": [
    "cadeia_custodia",
    "busca_pessoal_domiciliar",
    "ausencia_deficiencia_defesa",
    "prova_ilicita_derivada",
    "citacao_intimacao_interrogatorio",
    "cerceamento_defesa"
  ],
  "top_k": 24,
  "regenerar": false
}
```

O lote pode retornar `concluido`, `parcial` ou `erro`. Resultados concluidos
continuam salvos mesmo quando outro provedor falha. A rota
`GET /processo/{id}/analise-nulidades` lista todas as analises persistidas.
